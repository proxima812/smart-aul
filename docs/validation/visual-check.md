# T-009 · Чертёж и таверна

2026-11-08, ветка `t3/dadae87e`, база `e829ac9`. Minecraft 1.21.11,
Fabric API 0.141.4+1.21.11, Loom 1.15.5, игровая JVM Java 21.

## Повторение

```powershell
.\gradlew.bat build runGameTest
.\gradlew.bat runClientGameTest
git diff --check
```

`VisualGameTests` — entrypoint `fabric-client-gametest` в отдельном source set
`gametest`; в релизный JAR не попадает. Мир создаётся через TestWorldBuilder
в `build/client-gametest`, `run/saves` и `run/servers` не используются.
Каждый запуск начинает новый мир; PNG перезаписываются. Нужны окно и OpenGL.
API сверено с source JAR установленного fabric-client-gametest-api-v1 4.3.5.

## Постановка и проверки

Плоский мир, время фиксировано на 10000, игрок-наблюдатель, колокол колонии.
Обычный ConstructionJob `smart_colonies:tavern`, размеры 9×6×13, план читает
HouseBuilderTask. Fixture кладёт только пол. BlueprintPlans возвращает 701
недостающий блок; тест проверяет отсутствие готового пола в payload.
Вызов `/smart_aul blueprint on` от лица игрока, ожидание ненулевого mesh
BlueprintClient после реального S2C, ожидание отрисовки чанков. Два ракурса и
повтор кадра через 20 тиков; off должен очистить mesh. Reflection используется
только для чтения mesh в тесте, без тестовых hooks в production.

Затем fixture кладёт оставшиеся блоки того же плана и завершает задание;
создаются четыре взрослых жителя с хлебом. Автоматическое назначение ролей
сохранено (охранник отдыхать не должен). Минимум два посетителя должны дойти
до назначенных точек в пределах 1,5 блока за 500 клиентских тиков. Навигация,
выбор активности и LeisureTask выполняются обычным ИИ, без телепорта жителей.
Внешние кровати с HOME-памятью обеспечивают отдельную проверку сна; мест с
запасом (20), чтобы обычные жители колонии не заняли все кровати посетителей.

Рейд создаётся штатным менеджером Minecraft (игрок временно creative,
сложность normal, raids разрешены). Проверяется активность рейда у колонии,
за 40 тиков — прекращение VISITS и активности LEISURE. Рейд останавливается,
время 13000: за 600 тиков все выбранные посетители должны прекратить отдых и
сменить позицию; минимум один должен уснуть. Сон всех одновременно не проверяется.
Волны и победа над рейдом в этот сценарий не входят.

## Найденные проблемы и ограничения

- B-008: один прогон упал в строгом NetworkSynchronizer Fabric. Применён
  рекомендованный сообщением Fabric флаг disableNetworkSynchronizer только
  для client GameTest. Вместо него явные ожидания mesh/chunk render. Причина
  низкоуровневого рассогласования пакетов не установлена.
- При подготовке fixture исправлены: вызов blueprint-команды без игрока;
  отсутствие еды; ожидание отдыха от охранника; отсутствие/конкуренция кроватей.
  Это ошибки тестовой постановки, не подтверждённые дефекты мода.
- Стройка/списание материалов не проверяются: готовое здание ставит fixture.
  Не проверены полный цикл рейда, перезагрузка мира, моды рендера, дальние чанки.
- Предварительные прогоны с требованием сна каждого посетителя не прошли:
  один уже спал, второй менял HOME и искал свободную кровать, при этом оба
  ушли из таверны. Критерий соответствует запросу «время сна — уходят»:
  прекращение отдыха/смена позиции всеми и сон хотя бы одного. Гарантия сна
  каждого при конкуренции за кровати не установлена.
- Изменений production-кода и игровых ресурсов нет.
