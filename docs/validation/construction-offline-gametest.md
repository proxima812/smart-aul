# T-010 — стройка, NBT, офлайн-развитие и бюджеты поиска

Дата: 2026-11-08. Ветка: `t3/e8a70b46`. Minecraft 1.21.11, Fabric API
0.141.4+1.21.11, Java 21. Изменён только source set gametest и документация;
`src/main`, mappings и `build.gradle` не менялись. Тестовый Mixin D-004 сохранён.

## Сценарии

`ConstructionGameTests` выполняет реальный `HouseBuilderTask`: `shouldRun`,
`run`, `shouldKeepRunning`, `keepRunning`, `finishRunning`. Задание проходит
`loadPlan` с расчисткой, фундаментом и блоками шаблона. Маленький шаблон содержит
три стеклянных блока над готовым каменным грунтом. Он создаётся через штатный
StructureTemplateManager захватом тестовой структуры; прямых установок после
начала работы строителя нет. Строитель рядом со складом и всей постройкой;
vanilla AI отключён, task вызывается тестом по реальным серверным тикам.

- При трёх материалах только на общем складе строитель сам получает их и
  заканчивает задание со статусом COMPLETE. После каждого действия сумма
  предметов в сундуке, руке, инвентаре строителя и поставленных блоков равна 3.
  Пакет — один блок, development_speed=100; расход проверяется на каждом блоке.
  В конце склад и груз пусты, в мире ровно три целевых блока.
- Без материалов 25 тиков нет ни одного целевого блока и нет COMPLETE. Доставка
  тех же трёх предметов в сундук возобновляет работу до COMPLETE с тем же балансом.
- После первого блока задача штатно останавливается. ColonyWorldData записывается
  настоящими приватными методами сериализации, затем NbtIo записывает бинарный
  NBT в байты и читает его обратно. Загруженная колония заменяет исходную в мире;
  новый экземпляр HouseBuilderTask продолжает её. UUID, курсор и одно задание
  сохраняются, повторный NBT round trip также не создаёт дубль. Конечный баланс 3.
  Reflection применяется только в тесте для доступа к существующему NBT codec;
  тестовых API в релизный мод не добавлено.

`OfflineBudgetGameTests`:

- 1, 6 и 30 Minecraft-дней через сохранённый simulated_until и настоящий
  ConstructionManager (точка входа офлайн-развития). Начальное развитие отключено,
  население 8, отдельно нулевая перепись работников/еды и рабочая перепись.
  При голоде без работников нет производства, труда, домов и прироста.
  Рабочая колония получает разрешённые симуляцией кредиты, а не готовые дома и
  жителей: труд <=12000, дома <=4, рождения <=8, ресурс <=4096. Проверяются точные
  кредиты, повтор в том же тике и полное равенство производства 30 и 6 дней
  (offline_max_days=6). Это ограничение модели офлайн-производства, которое само
  по себе предусмотрено модом, а не запрет законной продукции работников.
- Реальный загруженный сундук с десятью входными предметами: OfflineDevelopment
  превращает шесть в шесть выходных, сохраняет резерв четыре; повтор даёт ноль.
- SearchBudget мира выдаёт шесть запросов за тик, стабильно отклоняет дальнейшие
  и восстанавливается на следующем тике.
- NavigationSearch с лимитом четыре узла возвращает безопасный неполный путь,
  не успех. Для временного лимита обработчик terrain занимает минимум 2 мс
  (spin без sleep); бюджет 1 мс останавливает поиск после первого узла. Нулевой
  nanos — штатное отключение временного лимита в контрольном поиске. Достаточный
  бюджет достигает цели.

Настройки и gamerule восстанавливаются после каждого callback в finally.
Строительные тесты убирают свои колонии, жителей и кеш шаблона. Тестовые данные
живут только в build/gametest; пользовательские миры не открывались.

## Проверки и ограничения

Команда: `gradlew.bat build runGameTest --console=plain`; `git diff --check`.
Итог: BUILD SUCCESSFUL; GameTest 11/11 PASS; developmentRegression 96 994 PASS,
Logic 935 PASS, fuzz 3000 карт / 9750 поисков / 1000 NBT / 64 JSON PASS.
JUnit XML: `build/reports/gametest/results.xml`; сохранённая копия `docs/validation/t010-gametest-results.xml`.

Первые запуски корректно вернули ненулевой exit code на ошибках стенда: не был
отмечен созданный склад, грунт не покрывал глубину фундамента, склад был добавлен
в runtime-список вместо штатной сохраняемой регистрации. Исправлен стенд;
проверки расхода и прогресса не ослаблялись. Дополнительный стенд конверсии сначала пытался положить десять нестакаемых предметов в один слот: настоящий сундук ограничил размер стека; исправлена раскладка в десять слотов. Подтверждённых новых багов src/main нет.

NBT round trip проверяет ColonyWorldData через бинарный формат в памяти, не
перезапуск JVM/сервера и не сохранение всех чанков/инвентарей на диск. Строитель
и сундук в этом сценарии остаются в том же ServerWorld. Проверка не доказывает
назначение профессии, дальний подход к складу, произвольные шаблоны, клиентскую
анимацию и визуальное поведение. Офлайн-время задаётся NBT, а не ожиданием 30 дней.
