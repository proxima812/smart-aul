# Навигация, перекрытие провалов и ратуша — 2026-11-06

## Реализация

Самостоятельная реализация ограниченного A* по подходам Baritone, без переноса
его исходников или клиентских зависимостей. Доступные движения учитывают размеры
сущности, подъём/спуск на один блок, безопасные диагонали и стоимость опасных
краёв/воды. Эвристика не складывает дважды одновременный подъём и горизонтальный
шаг. Очередь отбрасывает устаревшие стоимости, бюджет — 6000 узлов и 3 мс на
дополнительный поиск, при остановке возвращается реальный частичный путь.
Исполнение сохраняет углы обхода: опережающая точка выбирается только в пределах
прямого сегмента. На каждом обращении перепроверяются ближайшие восемь узлов.
Обычные рабочие задачи также используют дополнительный поиск, если ванильный
путь отсутствует или идёт вдоль опасного края.

Открытые провалы глубиной от трёх блоков рядом с жителями превращаются в задания
существующей системы ремонта. Один житель за проход, четыре соседние клетки,
очередь до 32 блоков, территория поселения и высота в пределах ±8 от ядра.
Опора ставится с существующего края; строитель должен стоять на твёрдом полу.
Перед установкой повторяются проверки, после успешной установки расходуется
материал. Сохраняются WorldEditPolicy/WorldEditScope, защита земли, материалов,
загрузки чанков, досягаемости и коллизий. При наличии доступных материалов срочное
задание может получить единственный строитель; обычный ремонт этого не делает.
Новые NBT-поля: `safety_covers`, `completed_safety_covers`; старые поля и ID не
переименованы. Устаревшие заявки отменяются, выгруженные не проверяются вслепую.

Одна ратуша определяется заданием шаблона `smart_colonies:town_hall`, без отдельного
дублирующего флага. Структура 9×6×9 содержит три таблички, обновляемые из состояния
поселения. ПКМ возвращает подробности в чат через существующий UseBlockCallback;
подход сверялся с [Fabric Events](https://docs.fabricmc.net/develop/events/).
Потребность стройки означает оставшиеся блоки без вычета складских запасов,
а не обещание точного дефицита с учётом замен материалов.

Генератор `tools/dev/generate_town_hall.py` воспроизводит
`src/main/resources/data/smart_colonies/structure/town_hall.nbt` без внешних библиотек.

- `gradlew.bat build`: компиляция, упаковка и существующие developmentRegression.
- Новая NavigationSafetyRegression: сравнение A* с независимым Дейкстрой на 30
  картах, диагонали, углы, обход провала, штраф опасного края, лестница, частичный
  путь, лимиты, классификация глубины, NBT старых и новых полей, ратуша после
  загрузки, физические таблички и вход. Minecraft сам прочитал NBT-шаблон.
- `python -m py_compile tools/dev/generate_town_hall.py`.
- Проверено присутствие новых классов и структуры в устанавливаемом JAR.
- `git diff --check` без ошибок; Git предупреждает о нормализации CRLF в части
  ранее изменённых файлов репозитория.

## Серверный сценарий

До запуска проверены процессы и порты. Отдельная копия
`run/servers/development/world` помещена в `run/servers/navigation-safety/world`.
Исходный тестовый мир и клиентские сохранения не открывались для изменения.
Запуск:

```powershell
.\gradlew.bat runDevelopmentServer --args="--universe ../navigation-safety --world world --port 25587 --nogui"
```

Сервер успешно загрузил Minecraft 1.21.11 и мод. Команда `place template` отдельно
подтвердила загрузку структуры и создание block entity таблички.
В поселении с ядром `718 65 372` включён `dev creative`, запрошен `tick sprint 1000`,
затем спринт прерван, creative остановлен, выполнены `save-all` и `stop`.
Ратуша в `722 78 388` завершена, сохранён прогресс `1545/1545`.
Таблички по координатам `724/726/728 80 389` содержали настоящие сводки:
«РАТУША», «ПЛАН РАБОТ», «ЗАПАСЫ», население и счётчики работ.
В сохранении зарегистрирован один завершённый блок перекрытия.

Сервер затем повторно запущен на той же копии, данные таблички прочитаны через
RCON, сохранение и остановка прошли штатно. В сохранении осталась одна ратуша
для каждого поселения, где она была запланирована; дубликатов не появилось.
Выбранные данные сохранены в `navigation-town-hall-evidence.json`.

Серверный запуск предшествовал последнему уточнению выбора точки на прямом
сегменте пути; это уточнение проверено регрессией и финальной сборкой.

## Ограничения доказательств

Это ускоренная серверная проверка, не доказательство обычной экономики.
Не проверялись клиентский вид здания, клик по доске живым игроком, обычный
строитель без снабжения creative и отдельные игровые сценарии защищённой земли.
Счётчик перекрытия не доказывает геометрию и причину конкретной установки;
контролируемый сценарий с искусственным провалом описан в TESTING_RU.md.
Сравнение производительности с прежней версией и Baritone не проводилось.
