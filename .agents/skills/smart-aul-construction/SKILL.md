# Строительство и защита территории

Пути указаны от корня. Основной пакет — `src/main/java/net/smartaul/village`.

## Точки входа

- `ConstructionManager`, `ConstructionJob`, `ConstructionBlockPlan`,
  `ConstructionStatus`, `HouseBuilderTask` — план, прогресс и выполнение стройки.
- `BuildingSiteSearch`, `BuildingSiteValidator`, `SiteCandidate`, `TerrainSupport`,
  `SearchBudget` — поиск и пригодность участка.
- `HouseTemplateRegistry`, `HouseTemplateSet`, `HousePurpose`, `*HouseTemplates`;
  структуры находятся в `src/main/resources/data/smart_colonies/structure`.
- `VillageRepair`, `RepairTask`, `RoadBuilderTask`, `WallBuilderTask`, `WallBlockPlan`.
- `WorldEditPolicy`, `WorldEditScope`, `PlayerBuildTracker`, `ProtectedLand`,
  `LandClaimManager`, `ColonyWorldData` — разрешения и учёт чужих построек.

## Сохраняемые условия

- Каждый блок в пакете ускоренной стройки отдельно проходит проверки материала,
  досягаемости, коллизий, загрузки чанка и допустимости изменения. Ускорение не
  должно увеличивать расход при неудачной установке или пропускать проверки.
- Используй существующий путь через `WorldEditPolicy` и `WorldEditScope`.
  Учитывай `allow_terrain_changes`, `mobGriefing`, защитные теги, блок-сущности,
  землю и блоки игрока. Не подменяй запрет прямым вызовом установки блока.
- Различай временно недоступный участок и исчерпанный поиск. Проверяй несколько
  шаблонов с ограниченным бюджетом, без полного сканирования мира каждый тик.
- При активной стройке ремонт не забирает единственного строителя; при нескольких
  работниках назначение ремонтника остаётся детерминированным. Ориентир —
  `config/DevelopmentPolicy.repairWorker` и его регрессии.
- В число домов для города входят завершённые общественные дома системы,
  а не просто найденные ванильные постройки и незавершённые планы.

## Проверка изменения

Проследи цикл: выбор участка → резерв/план → материалы → подход строителя →
поэтапные блоки → завершение/отмена → освобождение резервов. Для сохранённого
прогресса проверь NBT round trip через реальные классы. Подходящие сценарии:
препятствие игрока, недостаток материала, выгрузка чанка, один строитель при
ремонте, пакет из нескольких блоков и возобновление после загрузки мира.

Используй `smart-aul-validation` для запуска проверок; для новых NBT-полей —
`smart-aul-persistence`, для изменения NBT-шаблонов/ресурсов —
`smart-aul-fabric-integration`. Проверки видимой стройки требуют отдельного мира.
