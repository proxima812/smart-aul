# Конфиги и совместимость сохранений

Все пути — от корня репозитория.

## Источники схемы

- `src/main/java/net/smartaul/config/SmartAulConfig.java`, `VillageConfig.java`,
  `WorkConfig.java`, `RoleConfig.java`, `DebugConfig.java`, `DevelopmentPolicy.java`.
- `config/ConfigMigration.java` переносит `smart_colonies.json` в
  `smart_aul.json` только при отсутствии нового файла; старый файл остаётся.
- В `village/`: `ColonyWorldData`, `Colony`, `ConstructionJob`, `CreativeCityPlan`,
  `LandClaim` и другие классы с NBT-методами. Некоторые методы ещё называются `x*`.
- Реальные round-trip проверки —
  `src/regression/java/net/smartaul/village/DevelopmentRegression.java`.

## Правила изменения

1. Сначала найди чтение и запись поля, значения по умолчанию и всех потребителей.
   Публичный `smart_aul` и Java-пакет `net.smartaul` не означают переименование
   ресурсных ID, NBT-ключей, регистраций памяти или world data `smart_colonies`.
2. Для нового JSON-поля обеспечь разумное значение при отсутствии в старом файле;
   проверяй фактический путь десериализации Gson. Ограничения чисел и согласование
   min/max держи в существующем `DevelopmentPolicy.validate`, где это применимо.
3. Для NBT определи отсутствие/старый тип поля и обратное чтение. Сохраняй UUID,
   родительские связи, стадии стройки, груз экспедиции и курсоры режима. После
   изменения world data должен сохраняться dirty-state по принятому в классе пути.
4. Не перезаписывай существующий новый конфиг старым. Не удаляй старый конфиг
   после копирования. Изменение схемы должно иметь явный путь чтения старых данных.
5. Отличай сохраняемое состояние от кешей: после загрузки перепроверяй ссылки на
   сущности и чанки, не сериализуй живые объекты сервера вместо идентификаторов.

## Доказательства совместимости

Для изменения данных добавляй поведенческие проверки: старый документ без поля,
граничные/некорректные настройки, NBT запись→чтение через реальный класс,
повторная загрузка без дублирования. Для длительного creative-плана учитывай
время за пределами `int`, более шести деревень и миграцию прежнего `elapsed`.

`tools/dev/read_test_nbt.py <путь-к-файлу>` читает gzip-NBT и печатает JSON.
Используй на тестовом сохранении после штатного сохранения/остановки сервера;
утилита не является универсальным редактором миров и не читает region-файлы.
Сборка и игровые сценарии — в `smart-aul-validation/SKILL.md`.
