# Сборка и проверка Smart Aul

Работай из корня репозитория. Сценарии находятся в `TESTING_RU.md`.

## Сборка и автоматические проверки

```powershell
.\gradlew.bat --version
.\gradlew.bat build
# Отдельный запуск при работе над регрессиями:
.\gradlew.bat developmentRegression
git diff --check
```

На Unix используй `./gradlew`. Java target/toolchain — 21, wrapper — Gradle 9.4.1
на момент создания скилла. JVM для запуска Gradle и toolchain компилятора — разные
настройки; при несовместимости сначала проверь фактическую JVM и доступные JDK.
Не меняй target мода, чтобы обойти ошибку запуска Gradle.

`developmentRegression` — JavaExec с main-классом
`net.smartaul.village.DevelopmentRegression`, а не JUnit suite. Исходники лежат в
`src/regression/java`. `build` уже включает его через `check`; второй запуск без
причины не нужен. Для багфикса предпочитай проверку наблюдаемого поведения,
реальной сериализации и границ, а не поиск строки в исходниках. Существующие
проверки команд могут подтверждать регистрацию, но не выполнение в живом мире.

Для правок Python-утилит: `python -m py_compile tools/dev/development_rcon.py
tools/dev/read_test_nbt.py` (одной командой). Для правок только документации
проверяй пути, формат и diff; запуск Minecraft не требуется.

## Серверная и игровая проверка

```powershell
.\gradlew.bat runDevelopmentServer
```

Эта задача использует `run/servers/development`, где уже может быть тестовый мир.
Перед запуском проверь существующие процессы, каталог и конфигурацию сервера:
повторный запуск не должен конфликтовать с работающим сервером. Не принимай EULA
автоматически, если она не принята и пользователь не поручал этого.

- Используй отдельный тестовый мир/копию. Не открывай пользовательский мир на
  месте и не считай `dev off` откатом: выданные предметы и блоки уже изменили мир.
- Сначала зафиксируй исходное состояние и диагностические `status`, `progress`,
  `settlements`; затем выполни относящийся к задаче сценарий из `TESTING_RU.md`.
- `tools/dev/development_rcon.py` предназначен для локального dev-сервера: endpoint
  и параметры подключения зашиты в утилите. Перед использованием сверяй целевой
  сервер; не направляй её вслепую на другой процесс и не публикуй параметры доступа.
  Утилита пишет `run/logs/development-runtime-results.jsonl`.
- Для естественного развития используй отдельную копию без `supply`, `max` и
  выдачи населения. Проверка постановочной экспедиции не доказывает обычную отправку.
- Для persistence штатно сохрани/останови сервер и перезагрузи тот же тестовый мир.
  Для клиента запускай `runClient`, если визуальный тест входит в задачу.

## Артефакт и отчёт

Устанавливаемый результат текущей версии — `build/libs/smart-aul-1.1.0-dev.jar`,
не `-sources.jar`; после изменения версии найди фактическое имя. Для правок
упаковки проверь `fabric.mod.json`, entrypoint, Mixin-классы и ресурсы внутри JAR.
Запуск через Loom и запуск упакованного мода — разные уровни проверки.

Сохраняй полезные результаты в `docs/validation` при существенной игровой проверке:
ревизия/описание изменений, команды, исходное состояние, наблюдения и ограничения.
Не включай целые миры, секреты или все сгенерированные логи. Не выдавай прошлые
отчёты за новый запуск и не копируй историческое число checks как текущий результат.
